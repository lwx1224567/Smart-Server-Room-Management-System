# 统一可读编号

2026-10-19 已在当前开发库补齐此前盘点的各类可读编号。所有格式为两位字母前缀 + 上海时区日期 + 当日流水号（至少四位，超出自动扩位）。各类型分别计数，重复读取、补号或重启不会改变已有编号。

| 对象 | 字段或存储位置 | 前缀 | 当前已编号数量 | 实库示例 |
| --- | --- | --- | --- | --- |
| 告警 | `sp_alarm_number.alarm_code` / 接口 `alarmCode` | GJ | 44 | GJ202610170003 |
| 工单 | `sp_order_number.order_code` / 接口 `orderCode` | GD | 7 | GD202610190001 |
| 操作日志 | `sp_monitor_record.payload.logCode`，`kind=LOG` | RZ | 71 | RZ202610190004 |
| 采集请求 | 日志 `payload.requestCode`、`payload.response.requestCode` | QQ | 13 | QQ202610170006 |
| 采集批次 | `sp_ingest_batch.batch_code` / 接口 `batchCode` | PC | 13 | PC202610170006 |
| 历史备份 | `sp_source_backup.backup_code` | BF | 199 | BF202610150199 |
| 登录会话 | `console_session.session_code` / 登录响应 `sessionCode` | HY | 23 | HY202610190001 |

数量为本次补号完成时的快照；后续创建记录会继续分配，不应将此处数量作为固定验收值。

## 日期与关联规则

- 日志与请求优先使用记录的 `createdAt` / `observedAt`；同一机房的同一个原请求对应同一个 QQ 编号，其重试响应和日志中一致。
- 批次使用 `created_at`；备份使用该迁移的 `applied_at`；旧会话按当前固定 8 小时有效期，从 `expires_at` 反推创建时间。缺少有效日期时使用补号日期。
- 告警和工单继续使用各自已有映射表。新增的五类编号使用 `sp_readable_identifier` 和 `sp_readable_day_sequence`，通过事务行锁及唯一约束防止重号。
- 日志编号在机柜日志中展示；监测上报回执展示 QQ / PC 编号，历史上报表展示 QQ 编号。批次、备份和会话可在数据库中按新增编号列定位。
- 新日志在保存时编号，新采集批次和登录会话在创建时编号；应用就绪后幂等补齐历史记录及迁移备份。

## 内部字段保持原用途

这些可读编号是对外引用字段，不是替换底层主键。UUID、工单旧 ID、批次 `batch_id`、请求 `requestId`、通知关联继续保持原值。客户端重试仍提交原始 `requestId` / `batchId`，不要把 QQ / PC 编号作为新请求的幂等键。

登录 `token_hash` 及令牌继续保持安全随机性；HY 是会话管理编号，不能用于登录或冒充会话。编号注册表仅保存原标识的 SHA-256 摘要，不保存或输出明文登录令牌。

备份仅新增独立 `backup_code` 列，`payload` 原始正文、旧 `record_key` 和其中的关联 ID 不改写，避免失去历史还原依据。日志正文只补充 `logCode` / `requestCode` 展示字段，原请求参数及采集响应依据保留。

## 核对方式

```sql
SELECT batch_code, room_id, created_at
FROM sp_ingest_batch WHERE batch_code = 'PC202610170006';

SELECT backup_code, migration_id, table_name
FROM sp_source_backup WHERE backup_code = 'BF202610150199';

SELECT session_code, account_id, expires_at
FROM console_session WHERE session_code = 'HY202610190001';

SELECT JSON_UNQUOTE(JSON_EXTRACT(payload, '$.logCode')) AS log_code,
       JSON_UNQUOTE(JSON_EXTRACT(payload, '$.requestCode')) AS request_code
FROM sp_monitor_record
WHERE kind = 'LOG'
  AND JSON_UNQUOTE(JSON_EXTRACT(payload, '$.requestCode')) = 'QQ202610170006';
```

`scripts/BackfillReadableIdentifiers.java` 可执行补号和只读前后核对；已验证历史备份正文、原会话鉴权字段、批次去重键与摘要、告警和工单数据均保持原值，重复补号映射不变。前端类型检查及包含实库请求重试的相关后端测试通过。

部署后重启后端并刷新页面，旧服务进程需使用新版代码兼容新增的会话编号列。
