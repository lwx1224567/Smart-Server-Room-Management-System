AssistantAgentIntegrationTest仍为SpringBoot/真实数据库依赖测试，fixture含隔离库断言及数据库写入，不属于本轮可执行测试。

| 原覆盖目标 | 新协议验证 |

## 5. 当前架构与协议

完整架构图与字段约束见新技术说明，核心链路：

文字/语音转写 → InspectionAssistant → agent-assistant → agent-conversation → agent-client → AssistantAgentController → AssistantAgentService → IntegrationService模型工具网关 → 白名单校验 → 既有业务Service。

场景由服务端clientAction → 既有scene-action-executor → RoomScene → scene-result；主页明确选择/定位由home-scene-controls复用同执行器。前端不理解业务自然语言，不编排建单、指派、复检。

Agent前缀/api/v1/assistant/rooms/{room}，路由为GET session和POST session/end、chat、scene-result、confirm、confirmation/status、pending/dismiss。身份为现有管理员认证，页面标识隔离会话。JSON为R信封，SSE为status/message_start/delta/done/error，done携带原始会话。

14个工具包含5个资产工具、优先告警、监测、工单、准备建单、推荐人员、准备指派、准备复检、历史和场景动作。保留current room、稳定ID、分页/缺失值、等级排序、人员资格与有效推荐序号等既有约束。

写入仅在Agent确认卡片点击后提交pendingToken/kind/requestId；后端校验待办、有效期、权限、资源状态与幂等。文字/语音确认不写入；中断查询confirmation/status，不自动重提。此“唯一”限定Agent路径，不否认其他正式业务页面已有合法写入功能。

- 新文档按当前代码说明get_history：描述要求稳定资源身份，但schema与执行允许省略资源筛选，仍按当前机房调用既有Service。这是现状一致性待决策项；本阶段不收紧参数或修改业务行为。若要求强制“至少一种资源身份”，需另行批准语义调整及回归。

- 真实模型是否遵循工具字段、候选顺序、真实代理SSE缓冲、浏览器动画状态及并发事务仍未验证。
- 旧API删除可能影响仓库外旧客户端，风险已由用户明确接受；本轮不恢复兼容入口。
- 数据库集成测试迁移后只通过编译。测试profile、回滚和fixture数据库名断言不能替代启动前隔离审查；应用初始化仍可能产生数据库操作，不能擅自运行。
- 本轮未发现需要立即改变现有业务Service/权限策略/核心交互才能完成整理的阻断项；未做全面安全审计，不把未发现当作安全证明。
