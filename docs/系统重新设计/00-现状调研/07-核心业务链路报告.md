**当前实现（事实）**：可由POST ingest或collector拉取批次；ingest锁room，用(room,batchId)+digest幂等，验证实体归属、时间、有限数、数组上限和字段枚举，写reading/energy/monitor records后evaluate。RULE来自sp_monitor_record；evaluate找最新GOOD样本（REAL/DEMO均可归一REAL），验证单位/时效及上下阈值，异常生成/更新ALARM，并复制规则快照；恢复需持续时间/采样间隔，关联未完成工单时不自动越过工单复检。

## C. 告警→工单→指派→维修→复检→归档

**当前实现与状态（事实）**：

| 步骤 | 权限/前置条件 | 状态和数据行为 |
|---|---|---|
| 建单 | ADMIN；关联告警须存在且未恢复；锁机房 | 待受理；复制alarmSnapshot/cabinetId/deviceId/recordOrigin；同机房同告警未完成工单复用 |
| 领取 | MAINTAINER；待受理且未指派 | ownerAccountId为当前人，已接单 |
| 指派 | ADMIN；待受理/已接单/处理中；目标为启用维保 | 待受理变已接单，其余保留状态；发通知 |
| 开工 | 当前负责人；已接单 | 处理中 |
| 暂存 | 当前负责人；处理中 | 写process等，仍处理中 |
| 提交 | 当前负责人；处理中；cause/process/result必填 | siteChecked=true，verified=false，记录submittedAt，待复测 |
| 复检 | ADMIN手动或15秒调度 | 查询submittedAt之后、当前时间之前、同对象/指标/单位、GOOD样本；阈值/有效期/正常持续/最大间隔 |
| 通过 | passed=true | 已完成、verified=true、archivedAt；关联告警已恢复，通知 |
| 失败/不足 | passed=false/null | false返回处理中；null保持待复测，不伪造通过 |
