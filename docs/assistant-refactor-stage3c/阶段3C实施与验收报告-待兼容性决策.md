## 3. 兼容性停止原因及推荐方案（尚未执行）

触发用户要求的停止条件：无法确认旧API是否仍有外部调用方，删除或弃用可能破坏兼容。未取得调用方负责人确认、版本支持清单、访问统计或正式下线通知。仓库静态结果无法证明“没有外部调用”。

旧model并非新Agent工具循环：其读取数据库上下文并返回旧 {action:{...}} JSON，允许workflow、assign等旧前端动作，以及probeModel专用结果。该方法本身未执行建单/指派Service，但外部旧客户端可能消费动作并自行执行后续流程。不能直接转发新Agent：旧请求缺少明确的机房/页面会话语义，新协议涉及pending、场景token、requestId、SSE与按钮确认，转发会产生错误上下文或授权含义。

推荐待批准方案 D1：保留POST路径与现有认证/管理员保护，将正常授权请求改为明确 HTTP410 Gone，使用现有R.error统一信封，例如：

```json
{"code":410,"message":"旧助手接口已停用，请迁移到机房 Agent 会话接口；业务写入须通过确认卡片。","error":{"type":"LEGACY_ASSISTANT_RETIRED"},"requestId":"由现有响应机制生成","serverTime":"由现有响应机制生成"}
```

上面仅为字段示意，实施须按R类实际序列化契约断言。不得包含action.type，不伪造成功，不调用模型/数据库，不自动填机房，不创建Agent会话、不转发写入、不重试。可在同一批准范围内为成功鉴权后的410响应增加不含任意到期日的Deprecation/迁移Link提示；未经日期确认不擅自设置Sunset期限。

获批D1后具体可审阅变更边界：IntegrationController仅旧model方法改弃用响应；IntegrationService仅删除model(Map)、专属encode及无其他引用的TypeReference导入；保留完整模型工具网关及其他业务功能。更新ApiProtocolTest的弃用/信封/零模型调用断言；IntegrationGatewayTest把旧model/probe用例迁移为新网关同等错误格式、请求模型和上下文隔离断言，保留已有新工具断言；IntegrationApiTest仅旧接口断言改410，其视频控制测试保持，不运行数据库测试。补充鉴权后410、匿名401/非管理员403、旧参数不触发新Agent/业务写入的模拟测试及迁移文档。

D1风险：依赖HTTP200或503、action.reply/action.type、probeModel的外部客户端会改变行为。这是故意的显式停用，但仍是兼容破坏，必须由用户确认接受并安排客户端迁移，不能本轮自行实施。

不推荐D2：保留HTTP200并仅返回迁移文案。虽可维持部分旧信封读取，仍改变语义，也容易被客户端当成功。若选择D2，需明确客户端契约并禁止返回可执行action；同样等待批准。

不推荐直接404/删除入口：无外部兼容证明，且无法给使用方清晰迁移结果。最终删除必须另行确认受支持客户端已迁移，并明确保留期/下线责任。

当前暂时原样保留不代表旧逻辑符合最终架构，而是等待明确批准前的保护状态；没有宣称本轮已禁止旧动作返回或已完成统一架构。
