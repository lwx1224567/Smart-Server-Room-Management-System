# 部署指南

本文提供 Linux 单机部署参考：Nginx 托管前端静态文件，将 `/api/` 反向代理到本机 Spring Boot JAR。示例配置在根目录 `deploy/`，不是已经执行的服务器部署。

## 1. 准备环境与数据库

准备 JDK 17、MySQL 8、Nginx，以及构建用 Node.js（版本见根 README）和 Maven。使用独立数据库账号与数据库；先完成[初始化与演示数据](初始化与演示数据.md)，或按迁移说明准备正式台账库并仅执行管理员创建命令。

演示库只能用于展示；线上业务库不要导入演示样例。数据库需允许应用当前的建表与增量升级逻辑执行，备份应在升级前完成。

## 2. 构建前端

在 `前端/smart-park-guat-web/` 下执行：

```bash
npm ci
VITE_APP_BASE_API='' npm run build
```

空值使接口访问当前网站下的 `/api/v1/...`，与 Nginx 代理一致。PowerShell 可在前端目录创建本地 `.env.production`，内容为 `VITE_APP_BASE_API=`，再执行 `npm run build`；避免 Windows 环境变量空字符串被移除后变成 undefined。该环境文件已被忽略。构建时传入的地址会进入前端产物，部署后修改服务器变量不会改变已构建 JS。

将 `dist/` **内部内容**复制到 `/opt/smart-room/web/`，包括 `videos/monitor-demo.mp4`。不要把 Node 依赖目录放入站点根目录。

## 3. 构建后端

在 `后端/smart-park-guat-server/` 下执行：

```bash
mvn -DskipTests package
```

这里跳过依赖本地测试库的测试，仅用于打包；发布前应在隔离测试环境执行所需回归。将 `target/smartpark-0.0.1-SNAPSHOT.jar` 复制到 `/opt/smart-room/backend/`。

复制 `deploy/backend.env.example` 为服务器上的 `/etc/smart-room/backend.env`，填写真实数据库和 LLM 凭据，不把实际文件提交 Git。设置文件权限为 `600`，所有者为 root；systemd 系统服务可读取该文件并向非 root 应用用户传入变量。示例数据库名需按实际环境更换。

## 4. 配置 systemd

创建 `smartroom` 系统用户及组，为其准备后端工作目录的读取权限。将 `deploy/smart-room.service` 安装到 `/etc/systemd/system/smart-room.service`；如果 Java 不在 `/usr/bin/java`，修改 `ExecStart`。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now smart-room
sudo systemctl status smart-room
sudo journalctl -u smart-room -n 100 --no-pager
```

正常服务只读取运行配置，不设置 `BOOTSTRAP_ADMIN_PASSWORD`，不执行初始化工具。

## 5. 配置 Nginx

将 `deploy/nginx.conf` 放入 Nginx 的 `http` 配置上下文（例如站点配置目录），修改 `server_name` 为实际域名、`root` 为前端目录；确保 Nginx 用户有读取权限。

```bash
sudo nginx -t
sudo systemctl reload nginx
```

示例提供 HTTP 联调配置。公网使用时通过实际域名与证书配置 HTTPS，HTTP 跳转 HTTPS；后端绑定 `127.0.0.1`，不要额外公开 8080。SSE 使用 `proxy_buffering off` 和较长读取超时，避免小维流式回复被代理集中缓冲。

`try_files ... /index.html` 支持前端路由刷新，`proxy_pass` 不带末尾路径，保留完整 `/api/v1/` 请求地址。项目没有启用 Actuator，不能假设存在 `/actuator/health`。

## 6. 验收与更新

1. 打开站点并登录，确认 `/api/v1/auth/me` 成功，刷新业务路由不返回 Nginx 404。
2. 核对机房、资产、能耗与拓扑，确认视频可播放。
3. 配置 LLM 后验证一次普通查询和 SSE 回复；再使用测试告警验证确认、建单与维保流转。
4. 检查页面和服务器日志不显示真实密钥；核对演示来源与真实采集连接，不能用演示复测代替设备验收。
5. 发布更新前备份数据库和当前 JAR/前端版本，更新产物后重启后端、检查日志。应用启动可能修改表结构与历史数据，回滚 JAR 不等于回滚数据库，数据库恢复需单独规划。

本次仅验证了本地构建与初始化逻辑测试，示例 Nginx/systemd 配置仍需在实际服务器按上述步骤验收。
