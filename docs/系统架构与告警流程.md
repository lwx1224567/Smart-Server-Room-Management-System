# 系统架构与告警处理流程

## 系统架构

```mermaid
flowchart TB
    User[管理员与维保人员] --> Web[Vue 3 前端]
    Web --> UI[三维机房 / ECharts / 业务卡片]
    Web --> Store[Pinia / API 请求 / 会话状态]
    Store -->|HTTP JSON / Bearer Token| API[Spring Boot Controller]
    API --> Auth[ConsoleAccessFilter 身份与角色校验]
    Auth --> Services[台账 / 监测 / 能效 / 告警 / 工单服务]
    Auth --> Agent[小维 Agent 会话与确认流程]
    Agent --> Services
    Agent --> Integration[IntegrationService]
    Services --> DB[(MySQL 8)]
    Agent --> DB
    Integration -->|Chat Completions / 工具调用| LLM[DeepSeek 等模型服务]
    Integration --> Gateways[可选采集 / 视频 / 控制网关]
    Gateways --> Devices[真实设备与摄像头]
    Agent -->|SSE 回复与场景动作| Web
    Tool[独立 ProjectBootstrap 工具] -->|显式初始化| DB
```

- 前端负责三维表现、页面交互与服务端状态展示；模型密钥保留在后端。
- `/api/v1/` 接口由过滤器校验会话；大屏、台账及外部集成等接口要求管理员角色，维保人员使用个人工单和通知接口。
- 小维通过服务端工具访问业务能力；需要确认的写操作生成确认卡片，提交确认后才执行。前端场景动作的成功不等于物理设备操作成功。
- MySQL 保存台账、监测记录、能耗、工单、通知、会话与编号映射。当前部分 schema 升级由服务启动逻辑承担，没有自动扫描全部 SQL 的 Flyway 配置。
- 公共演示工具不属于 Web 请求路径，不会提供免登录的创建管理员接口。

## 告警与维修闭环

```mermaid
flowchart TD
    A[采集指标或录入演示指标] --> B[保存读数并评估规则]
    B --> C{是否命中告警条件}
    C -->|否| Z[继续监测]
    C -->|是| D[生成或更新告警]
    D --> E[管理员查看 / 小维查询分析]
    E --> F{通过小维发起写操作}
    F -->|是| G[生成确认卡片]
    G --> H{用户确认}
    H -->|取消| E
    H -->|确认| I[校验权限 / 状态 / 确认令牌]
    F -->|否 直接页面操作| I
    I --> J[创建关联工单：待受理]
    J --> K[管理员指派或维保领取：已接单]
    K --> L[维保开始处理：处理中]
    L --> M[提交原因 / 措施 / 结果：待复测]
    M --> N[自动复检或管理员触发复测]
    N --> O{提交后的有效监测证据}
    O -->|不足或过期| P[保持待复测并继续等待]
    P --> N
    O -->|不通过| L
    O -->|通过| Q[工单已完成 / 告警已恢复 / 通知归档]
```

实际工单状态为 `待受理 → 已接单 → 处理中 → 待复测 → 已完成`；复检不通过回到 `处理中`，缺少有效证据保留 `待复测`。管理员指派已有处理中工单时不会无条件重置状态。

重复关联同一未恢复告警时，服务优先返回已有未完成工单。操作可携带 `expectedState` 检查状态、负责人和更新时间，冲突返回 409 后应重新读取。演示复检与真实证据复检具有不同含义，不应将演示结果作为设备恢复凭证。
