# 前端项目结构与逐文件职责

以 2026-10-16 工作区实际代码为准。前端根目录：`前端/smart-park-guat-web/`。本文中的文件路径均相对于该目录。

## 1. 先理解项目如何运行

技术栈为 Vue 3、Vite、TypeScript/JavaScript、Vue Router、Pinia、Element Plus、ECharts。三维部分使用 scene/vendor 中的 Three.js，视频使用 hls.js，对话内容使用 markdown-it。

```text
index.html → src/main.ts → App.vue → router/index.ts
                                      ├─ /login → 登录页
                                      ├─ /maintenance → 维保后台
                                      └─ layouts/index.vue
                                           ├─ /user → 用户管理
                                           └─ /home → 首页入口
                                                ├─ 机房概览 / 机柜详情
                                                ├─ 能耗 / 告警
                                                ├─ 资产 / 网络拓扑
                                                └─ 三维场景、巡检助手
```

路由守卫先校验会话，再按 ADMIN、MAINTAINER 分流。首页底部五个业务菜单通过 `/home?business=operations|energy|alarm|assets|topology` 切换；机柜详情是首页内部状态，不是独立路由。首页有六类驾驶舱，是因为运维入口下还区分机房概览和机柜详情。

```text
前端根目录
├─ src/
│  ├─ api/          接口路径、请求参数及请求封装
│  ├─ assets/       由构建工具处理的图片和全局样式
│  ├─ components/   全局或跨页面复用组件
│  ├─ layouts/      页面框架、顶部栏和菜单
│  ├─ router/       URL 与页面映射、登录和角色守卫
│  ├─ services/     会话、工单、天气等业务服务
│  ├─ stores/       Pinia 台账、监测和菜单状态
│  ├─ types/        共享类型与旧 JS/Vue 兼容声明
│  ├─ utils/        身份解析、格式转换等工具
│  └─ views/        路由页面和首页内部业务模块
├─ public/          按原路径访问的静态资源
├─ e2e/platform/    浏览器业务流程测试和接口模拟
├─ tests/platform/  身份、适配、展示和数据口径测试
├─ scripts/         独立 API 与助手检查脚本
├─ test-results/    测试输出
├─ dist/            构建产物
└─ node_modules/    安装依赖
```

## 2. 数据和职责边界

当前存在两套请求入口，修改时应沿用调用模块的语义：

| 入口                     | 当前用途                            | 返回及错误处理                                   |
| ------------------------ | ----------------------------------- | ------------------------------------------------ |
| `api/platform/client.ts` | `/api/v1` 台账、监测相关平台请求    | Axios，提取 data，统一数据来源分类，处理会话过期 |
| `services/console.ts`    | `/api/console` 登录、会话及后台业务 | fetch，维护共享 auth 和 sessionStorage 中的会话  |

正式台账通常经过 `api/platform → stores/platform → useHomeSceneData → platform-scene-adapter → RoomScene → scene.ts`。监测数据由 `stores/monitoring` 供图表、告警和场景同步使用。工单由 `services/work-orders.ts` 在管理员、助手和维保页面之间共享。

`demo/` 保存演示数据与兼容逻辑，但正式模块中仍有代码导入这些数据，因此不能仅凭目录名判断它们已废弃。`scene/SOURCE.md` 是早期移植说明，其中“全部本地模拟”“当前没有模型请求”等描述已落后于现有接口和 Agent 实现，应作为历史记录阅读。

## 3. 新代码应该放哪里

| 要修改的内容                            | 优先位置                                                     |
| --------------------------------------- | ------------------------------------------------------------ |
| 新路由、登录限制、角色跳转              | `src/router/index.ts`                                        |
| 顶部入口、全局布局、业务菜单与 URL 同步 | `src/layouts/`、`src/components/BusinessMenu/`               |
| 新增平台接口                            | `src/api/platform/`；共享请求规则进 `client.ts`              |
| 台账缓存、机柜选择与详情                | `src/stores/platform.ts`                                     |
| 监测、告警、能耗查询状态                | `src/stores/monitoring.ts`                                   |
| 跨页面工单业务                          | `src/services/work-orders.ts`                                |
| 首页导航、助手和场景协调                | `src/views/home/composables/useHomeDashboard.ts`             |
| 首页数据加载与场景同步                  | `src/views/home/composables/useHomeSceneData.ts`             |
| 驾驶舱中的一张卡片                      | 对应 `cockpit/<业务模块>/components/`                        |
| 三维模型、交互、巡检动画                | `src/views/home/scene/`                                      |
| 助手对话、意图、语音或 Agent            | `src/views/home/assistant/`                                  |
| 共享实体类型、身份类型                  | `src/types/platform.ts`、`platform-identity.ts`              |
| 无页面依赖的身份、等级、时间或展示转换  | `src/utils/`                                                 |
| 跨页面 UI                               | `src/components/`；仅首页复用 UI 放 `views/home/components/` |

卡片按业务职责命名，例如 `RoomInfoCard.vue`、`ElectricalAlarmsCard.vue` 和 `CabinetControlCard.vue`。位置在驾驶舱 index.vue 中决定；修改布局无需重命名组件。`components/index.ts` 集中导出卡片，模块内共享实现放 shared。

整理后，驾驶舱目录统一为 `room`、`cabinet`、`energy`、`alarms`、`assets`、`topology`。资产页按布局、composables 和 styles 分开；机柜控制位于 useCabinetControls.ts。首页详细导航见 `src/views/home/README.md`。

## 5. 维护约定

- API 放 src/api，共享状态放 src/stores；登录、工单等跨页面业务服务放 src/services。
- 业务卡片放所属驾驶舱，跨业务 UI 放 home/components，跨页面 UI 放 src/components。
- 页面入口负责布局，复杂数据与交互协调放 composables，长样式放 styles。
- demo 和类型声明仍有运行或编译引用，不按名称删除。
- dist、node_modules 和 test-results 由构建、依赖管理和测试工具维护，不作为业务源码整理。

### 小维 Agent 当前协议

当前统一入口、工具、确认和场景契约以 [小维 Agent 当前架构与接口](../../docs/小维Agent当前架构与接口.md) 为准。`agentEnabled` 为兼容的固定能力元数据，前端不据此切换本地规则模式。
